Prompt Code Review — Copilot

Prompt padronizado para revisão de procedures SQL antes de abrir ou comentar um PR

Pré-requisitos
  • ✅ Estar na branch que será analisada
  • ✅ Ter o projeto aberto no VS Code (workspace completa)
  • ✅ Ter o Copilot habilitado
Passo a passo
1. Posicione-se na branch
Garanta que você está na branch correta que deseja analisar.
2. Gere o diff com a master (atualizado)
Execute os comandos: 
git fetch origin
git diff origin/master | clip
O git fetch atualiza o origin/master com o remoto.
O | clip copia automaticamente o resultado para a área de transferência.
3. Cole o diff no VS Code
Crie um arquivo temporário (ex: review_diff.txt) e cole o conteúdo.
4. Atenção — Papel do desenvolvedor
O prompt deve ser utilizado como base de apoio para análise.

A revisão final é responsabilidade de quem está analisando o código. Avalie criticamente cada ponto retornado pelo Copilot e valide:
• Se o problema realmente se aplica ao contexto
• Se a sugestão faz sentido para o negócio e padrão do projeto
• Se existe impacto colateral não identificado

Não utilize o resultado de forma automática.
5. Use o Copilot
Cole o prompt abaixo no Copilot Chat e em seguida o diff.
6. Analise o retorno
O resultado virá em Markdown, pronto para comentário no PR.
7. Importante
A análise é mais eficaz com o projeto aberto no VS Code (contexto do workspace).
Prompt para uso
Revise o diff abaixo considerando somente arquivos de procedures SQL (.sql).
Faça a revisão sob os seguintes critérios, em ordem de prioridade:

🔴 Erros claros e óbvios de SQL
• Uso incorreto de funções (ISNULL(x, x), NOT EXISTS com lógica invertida, etc.)
• Referências a tabelas temporárias inexistentes na procedure atual
• Variáveis usadas antes de serem populadas
• Inconsistência entre ##temp e #temp
• Ausência de SET XACT_ABORT ON
• Inconsistência de schema em funções

🟠 Coerência e erros de lógica de negócio
• Validações incompletas
• Atualizações em tabelas globais indevidas
• Exclusões sem filtro adequado
• Ausência de guarda @cd_retorno
• Falhas silenciosas sem erro

🟡 Validações faltantes em APIs
• Falta de validação de pertencimento entre parâmetros
• Combinações inválidas aceitas
• Mensagens inconsistentes

🔵 Padronização
• Nome incorreto em @nm_proc
• Padrão de guarda inconsistente
• Ausência de SETs padrão
• Inconsistência de nomenclatura

Para cada observação, indique:
- Arquivo / procedure
- Trecho do código
- Sugestão objetiva de correção

Retorne o resultado em formato Markdown, separando claramente cada tópico (🔴 🟠 🟡 🔵) em seções distintas.
